## Розгортання

Після додавання адмінки потрібен постійний Node-сервер і диск для SQLite. Одного завантаження `dist` на статичний хостинг недостатньо. Сервер обслуговує і API, і зібраний фронтенд.

```bash
npm ci
npm run build
DATA_DIR=/var/lib/beauty-space npm run admin:setup
DATA_DIR=/var/lib/beauty-space APP_ORIGIN=https://your-domain.example npm start
```

Каталог `DATA_DIR` має бути доступний для запису користувачу процесу й зберігатися між розгортаннями. Перед сервером потрібен HTTPS reverse proxy: `APP_ORIGIN` — точний публічний origin без шляху. Сервер за замовчуванням слухає `127.0.0.1:3001`; `API_PORT` та `HOST` можна встановити змінними середовища. У production cookie має прапорець Secure. API дозволяє мутації лише з налаштованого origin. Початковий пароль генерується командою setup, існуючий не замінюється. Продакшн не запускається без налаштованого HTTPS origin та облікових даних.

Використовуйте один сервер із постійним диском. Якщо потрібен serverless або кілька інстансів, сховище та сесії треба перенести до зовнішньої БД. Reverse proxy не повинен напряму роздавати корінь репозиторію чи `DATA_DIR`.

Сайт відкриває Direct/Telegram, не надсилає повідомлень і не підтверджує бронювання автоматично.

## Як керувати прайсом

1. Відкрийте `/admin` і введіть пароль із локального файлу доступу.
2. Оберіть категорію. Ціни приймають `550 грн`, `1 000 грн`, `50/70 грн`. На першому екрані відображаються перші дві конкретні послуги разом із їхніми цінами.
3. Натисніть «Зберегти зміни». Усі зміни в усіх категоріях публікуються разом, без rebuild. Нові відвідувачі бачать їх одразу; вже відкрита сторінка перевіряє оновлення при поверненні у вкладку й кожні 30 секунд.
4. «Скасувати зміни» після підтвердження завантажує поточний опублікований прайс. Незбережена чернетка живе у вкладці; браузер попереджає перед її закриттям.

Редактор змінює ціни, назви, склад, примітки й пояснення процедур. Можна додавати та прибирати 1–30 позицій у кожній категорії. Legacy `summary` лишається в JSON для сумісності; ручна ціна «від» більше не використовується. При зміні в іншій вкладці сервер відхиляє застарілу редакцію. У локальному Node доступ перевіряється сервером, сесії живуть 12 годин; вихід відкликає сесію. Пароль зберігається як scrypt-хеш, cookie — HttpOnly/SameSite=Strict; невдалі спроби входу обмежені. Production використовує Cloudflare Access.

Прайс, історія його версій і сесії зберігаються в `.data/studio.sqlite`. Початковий файл `src/data/prices.ts` використовується лише при створенні бази; його редагування не перезапише вже опубліковані ціни. Для резервної копії зупиніть API й скопіюйте весь `DATA_DIR`, включно з auth.json. Тести використовують окрему `.test-data` та тимчасову БД, без змін робочого прайсу.

Після вибору домену встановіть `APP_ORIGIN`: production-сервер автоматично сформує absolute `og:image`, `og:url`, canonical і sitemap. Фото hero локальні, WebP; галерея відкладена. Шрифти також завантажуються із сайту, з `font-display: swap` та окремими наборами символів через `unicode-range`; зовнішнього CSS Google Fonts немає. Джерела й ліцензії: [src/assets/fonts/README.md](src/assets/fonts/README.md).

Фото реальної роботи на першому екрані нерухоме на desktop/mobile і за будь-яких motion preferences. Галерея зберігає керування, lightbox і врахування reduced motion.

Міграція `expanded-portfolio-v1` одноразово додає нові роботи до наявної галереї, зберігаючи попередні редагування; після видалення через адмінку вони не повертаються при перезапуску.

## Зміна пароля

У локальному `/admin` відкрийте «Локальний пароль», введіть поточний пароль, новий (12–256 символів) і його підтвердження. Новий пароль має відрізнятися від поточного. Перед зміною опублікуйте або скасуйте чернетки в інших розділах. Після успішної зміни всі локальні сесії завершуються, зокрема поточна; увійдіть із новим паролем. Це не змінює вхід за поштою на основному сайті.

Сервер перевіряє поточний пароль, сесію та origin, обмежує невдалі спроби. `auth.json` атомарно замінюється новою сіллю та scrypt-хешем із правами `600`; відкритий пароль не записується. Старий файл початкового доступу `admin-access.txt` видаляється. Збережіть новий пароль у своєму менеджері паролів. Сесії прив’язані до версії облікових даних, тому старі cookie не працюють навіть після відновлення застарілого запису сесії. Перезапуск сервера для застосування нового пароля не потрібен.

Після першого оновлення на цю версію адмінка може попросити увійти знову через додану перевірку версії сесії. Функція призначена для зміни відомого пароля; відновлення забутого пароля через email не реалізоване.

## Окремий доступ власника

Сервер підтримує необов’язковий `DATA_DIR/owner-auth.json` із полями `salt` і `hash` у тому самому scrypt-форматі, що й основний пароль. Обидва паролі працюють через звичайну форму `/admin`; пароль власника також можна вказати як поточний, щоб змінити основний пароль у вкладці «Локальний пароль». Зміна основного пароля не змінює пароль власника, але завершує всі локальні сесії.

Файл власника має права `600`, виключений з Git і недоступний через Vite. Для розгортання його потрібно приватно перенести до `DATA_DIR` на сервері; він не надходить із GitHub. Видалення файлу вимикає цей спосіб входу, а зміна або видалення його хеша робить попередні сесії недійсними. Пароль власника через вебформу не редагується. Резервні копії цього файлу слід зберігати разом з іншими приватними серверними даними.

## SEO та запуск на домені

Кожна з трьох публічних сторінок отримує повний HTML через React SSR: контент, актуальні ціни, контакти та галерею видно до завантаження JavaScript. Браузер гідратує той самий snapshot. Прайс на головній використовує native details і відкривається без JavaScript. Ціни у видимому інтерфейсі та JSON-LD оновлюються зі спільного провайдера після публікації в адмінці.

Головна має title, description, canonical, Open Graph / Twitter metadata. JSON-LD пов’язує `BeautySalon`, `WebSite`, `WebPage` та каталог усіх послуг на головній. Пропозиції використовують опублікований прайс; неоднозначні ціни через «/» залишаються текстом без вигаданого точного значення. Рейтинги та координати не вигадуються. Зображення для поширення — `public/images/social-preview.jpg` (1200×630).

`/robots.txt` і `/sitemap.xml` генеруються однаково в Express та Cloudflare Worker. Sitemap містить `/`, `/pedicure`, `/laminuvannia-vii`. На головній збережено всі шість категорій; окремі сторінки мають цільові ціни та роботи. `/index.html` перенаправляється на `/` зі збереженням query-параметрів. Невідомі сторінки повертають 404. Адмінка й приватні API виключені з індексації; це доповнює авторизацію, а не замінює її.

Встановіть `APP_ORIGIN=https://ваш-домен` і запускайте через `npm start` після `npm run build`. Canonical та всі абсолютні SEO-посилання беруться тільки з цього налаштування, а не з Host-заголовка. Без налаштованого origin головна HTML-сторінка отримує `noindex`, canonical відсутній, sitemap повертає 404.

`npm run build` створює браузерну збірку в `dist/` та Node renderer у `.server/render-public.mjs`. Для Node deployment потрібні обидва каталоги й залежності; `.server/` не роздається як публічний файл. Worker включає renderer у свою збірку. Vite на 5173 призначений для розробки; перевіряти серверний HTML слід через Express після збірки або через Worker. `npm run test:server` сам збирає Node renderer; перед `npm run test:worker` виконайте `npm run build`.

Актуальне незалежне дослідження, карта запитів і дії після розгортання: [docs/seo/README.md](docs/seo/README.md). Публікація коду не замінює перевірку в Google Search Console та налаштування Google Business Profile; фактичні позиції вимірюються після індексації.


## Нові поля контенту та історія D1

У «Контакти» редагуються графік, поверх/вхід, відео маршруту та опис студії. Порожній графік прибирає години зі structured data. При зміні адреси заново заповніть поверх і відео входу. У «Роботи» категорія фото визначає сторінку послуги; окреме поле «Призначення фото» обирає головну обкладинку. Без такого запису показується стандартна обкладинка. «Ціна категорії» залишається редагованою й видимою в розгорнутому прайсі; на першому екрані наведено ціни конкретних процедур.

Node зберігає ревізії як раніше. Для Cloudflare підготовлено additive `0004_document_history.sql`; перед її застосуванням і rollback прочитайте [безпечний порядок](docs/seo/release-checklist.md). Статистичні таблиці та ідентифікатори збережено. Beacon і кліки тепер працюють на всіх трьох public routes; admin виключено. Клік не означає підтверджений запис, а D1 counters не містять джерело переходу.
