# Beauty Space Victoriya

Cloudflare deployment (Workers, D1, R2, email access): [CLOUDFLARE.md](./CLOUDFLARE.md).

Адаптивний українськомовний landing page на React, TypeScript і Vite. Tailwind CSS v4, clsx / tailwind-merge, Framer Motion, Lucide React. Google Fonts: Cormorant Garamond і Manrope.

## Запуск

Потрібен Node.js 24+. Сервер використовує вбудований `node:sqlite`.

```bash
npm ci
npm run dev
```

Команда запускає Vite на http://127.0.0.1:5173 і API на порту 3001. Адмінка: http://127.0.0.1:5173/admin. При першому локальному запуску автоматично створюються база та випадковий пароль у `.data/admin-access.txt`. Логін не потрібен, лише пароль. Цей файл приватний, не доступний через сайт і виключений з Git. Перенесіть пароль у свій менеджер паролів; текстовий файл після цього можна видалити, `auth.json` треба зберегти.

```bash
npm run build    # TypeScript + production bundle у dist/
npm run preview # локальний перегляд збірки; API має працювати через npm run dev:api
npm run lint
npm run test:server # авторизація, валідація, конфлікти, persistence, logout, rate limit
npx playwright install chromium
npm test        # desktop/mobile, редактор, публікація для іншого браузера, галерея, доступність
```

## Розгортання

Після додавання адмінки потрібен постійний Node-сервер і диск для SQLite. Одного завантаження `dist` на статичний хостинг недостатньо. Сервер обслуговує і API, і зібраний фронтенд.

```bash
npm ci
npm run build
DATA_DIR=/var/lib/beauty-space npm run admin:setup
DATA_DIR=/var/lib/beauty-space APP_ORIGIN=https://your-domain.example npm start
```

Каталог `DATA_DIR` має бути доступний для запису користувачу процесу й зберігатися між розгортаннями. Перед сервером потрібен HTTPS reverse proxy: `APP_ORIGIN` — точний публічний origin без шляху. Сервер за замовчуванням слухає `127.0.0.1:3001`; `API_PORT` та `HOST` можна встановити змінними середовища. У production cookie має прапорець Secure. API дозволяє мутації лише з налаштованого origin. Початковий пароль генерується командою setup, існуючий не замінюється. Продакшн не запускається без налаштованого HTTPS origin та облікових даних.

Використовуйте один сервер із постійним диском. Якщо потрібен serverless або кілька інстансів, сховище та сесії треба перенести до зовнішньої БД. Reverse proxy не повинен напряму роздавати корінь репозиторію чи `DATA_DIR`.

Сайт відкриває Direct/Telegram, не надсилає повідомлень і не підтверджує бронювання автоматично.

## Як керувати прайсом

1. Відкрийте `/admin` і введіть пароль із локального файлу доступу.
2. Оберіть категорію. Ціни приймають `550 грн`, `1 000 грн`, `50/70 грн`. Ціна на картці категорії редагується окремо й може мати префікс `від`.
3. Натисніть «Зберегти зміни». Усі зміни в усіх категоріях публікуються разом, без rebuild. Нові відвідувачі бачать їх одразу; вже відкрита сторінка перевіряє оновлення при поверненні у вкладку й кожні 30 секунд.
4. «Скасувати зміни» після підтвердження завантажує поточний опублікований прайс. Незбережена чернетка живе у вкладці; браузер попереджає перед її закриттям.

Редактор змінює ціни та коротку ціну категорії. Назви, описи, склад і кількість послуг поки змінюються в коді. При зміні в іншій вкладці сервер відхиляє застарілу редакцію, щоб не затерти нові ціни. Авторизація перевіряється сервером, сесії живуть 12 годин; вихід відкликає сесію. Пароль зберігається як scrypt-хеш, cookie — HttpOnly/SameSite=Strict; невдалі спроби входу обмежені.

Прайс, історія його версій і сесії зберігаються в `.data/studio.sqlite`. Початковий файл `src/data/prices.ts` використовується лише при створенні бази; його редагування не перезапише вже опубліковані ціни. Для резервної копії зупиніть API й скопіюйте весь `DATA_DIR`, включно з auth.json. Тести використовують окрему `.test-data` та тимчасову БД, без змін робочого прайсу.

Після вибору домену встановіть `APP_ORIGIN`: production-сервер автоматично сформує absolute `og:image`, `og:url`, canonical і sitemap. Фото hero локальні, WebP; галерея відкладена, шрифти з display=swap, анімації поважають prefers-reduced-motion. Google Fonts завантажуються зовні; галерея та всі фото працюють локально.

## Як змінювати фото робіт

1. Відкрийте `/admin` → «Роботи». Картки відповідають порядку фото на сайті; можна мати від 1 до 30 робіт.
2. Оберіть файл JPG, PNG або WebP до 8 МБ і 25 мегапікселів. Сервер перевіряє фото, виправляє орієнтацію, зменшує до 1600 px і зберігає WebP без EXIF. Анімації не підтримуються.
3. За потреби змініть назву, підпис та посилання на допис Instagram. Після заміни фото старе посилання очищається; нове заповнювати необов’язково.
4. Додавайте роботи через поле «Додати роботу», переставляйте стрілками та видаляйте кнопкою кошика. Зміни залишаються чернеткою до публікації. Натисніть «Опублікувати роботи». Саме завантаження файлу ще не змінює галерею на сайті. Нові відвідувачі бачать публікацію одразу, відкриті вкладки оновлюються при поверненні або протягом 30 секунд.

Чернетки зберігаються під час перемикання вкладок адмінки та повторного входу після завершення сесії, але не після перезавантаження сторінки. Браузер попереджає про незбережені зміни. «Скасувати зміни робіт» після підтвердження завантажує опубліковану версію. Сервер відхиляє застарілі редакції з інших вкладок.

Галерея й історія публікацій зберігаються в `studio.sqlite`, завантажені фото — у `DATA_DIR/media` (локально `.data/media`). Резервна копія має включати обидва. Початкова галерея з `src/data/gallery.ts` застосовується лише один раз. Невикористані завантаження не видаляються автоматично, щоб зберегти фото для чернеток та історії версій.

## Зміна пароля

У `/admin` відкрийте «Безпека», введіть поточний пароль, новий (12–256 символів) і його підтвердження. Новий пароль має відрізнятися від поточного. Перед зміною опублікуйте або скасуйте чернетки в інших розділах. Після успішної зміни всі сесії завершуються, зокрема поточна; увійдіть із новим паролем.

Сервер перевіряє поточний пароль, сесію та origin, обмежує невдалі спроби. `auth.json` атомарно замінюється новою сіллю та scrypt-хешем із правами `600`; відкритий пароль не записується. Старий файл початкового доступу `admin-access.txt` видаляється. Збережіть новий пароль у своєму менеджері паролів. Сесії прив’язані до версії облікових даних, тому старі cookie не працюють навіть після відновлення застарілого запису сесії. Перезапуск сервера для застосування нового пароля не потрібен.

Після першого оновлення на цю версію адмінка може попросити увійти знову через додану перевірку версії сесії. Функція призначена для зміни відомого пароля; відновлення забутого пароля через email не реалізоване.

## Окремий доступ власника

Сервер підтримує необов’язковий `DATA_DIR/owner-auth.json` із полями `salt` і `hash` у тому самому scrypt-форматі, що й основний пароль. Обидва паролі працюють через звичайну форму `/admin`; пароль власника також можна вказати як поточний, щоб змінити основний пароль у вкладці «Безпека». Зміна основного пароля не змінює пароль власника, але завершує всі сесії.

Файл власника має права `600`, виключений з Git і недоступний через Vite. Для розгортання його потрібно приватно перенести до `DATA_DIR` на сервері; він не надходить із GitHub. Видалення файлу вимикає цей спосіб входу, а зміна або видалення його хеша робить попередні сесії недійсними. Пароль власника через вебформу не редагується. Резервні копії цього файлу слід зберігати разом з іншими приватними серверними даними.

## SEO та запуск на домені

У production головна сторінка отримує від сервера актуальні title і description з послугами, містом, адресою та телефоном. Open Graph / Twitter Card використовують брендове прев’ю `public/images/social-preview.jpg` (1200×630). JSON-LD `BeautySalon` включає контакти, адресу, карту, сайт і соцмережі; рейтинг, години роботи та координати не вигадуються. Після редагування контактів HTML наступного запиту одразу оновлюється. Початкові контакти також передаються React, щоб не чекати API для першого показу сторінки.

`/robots.txt` і `/sitemap.xml` генеруються сервером. Sitemap містить лише головну сторінку: секції-якорі не є окремими URL. `/index.html` перенаправляється на `/`; невідомі сторінки повертають 404. `/admin` і `/admin/` отримують `noindex` у HTML та `X-Robots-Tag`, API також виключений з індексації. Адмінка залишається доступною краулеру, щоб він міг прочитати `noindex`. Це доповнює авторизацію, а не замінює її.

Встановіть `APP_ORIGIN=https://ваш-домен` і запускайте через `npm start` після `npm run build`. Canonical та всі абсолютні SEO-посилання беруться тільки з цього налаштування, а не з Host-заголовка запиту. У локальному режимі сервер забороняє індексацію, не створює canonical на localhost і повертає 404 для sitemap. Vite на 5173 призначений для розробки; серверний SEO-HTML локально можна перевірити на порту 3001 після збірки.

Інтерактивна сторінка залишається React SPA. Без JavaScript сервер віддає читабельний прайс, контакти та посилання запису в `noscript`; метадані й JSON-LD доступні в початковому HTML. Це не повний SSR всіх компонентів.

Після публікації підтвердьте домен у Google Search Console, додайте `/sitemap.xml` та перевірте головну через URL Inspection і Rich Results Test. Для локального пошуку також варто підтримувати актуальні дані у Google Business Profile. Індексація та позиції залежать від Google; локальна перевірка коду не означає, що сайт уже з’явився в пошуку.
