# Реалізація та карта змін

Кандидат підготовлено 2026-10-01 від `d4c9a30` у гілці `seo/local-intent-2026-10-01`. Production-розгортання і remote міграція не виконувалися.

Подальше візуальне уточнення за окремою вимогою власника: головні фотографії замінено на [атмосферні обкладинки](../hero-images.md), явно відокремлені від реальних робіт. Опис первинного SEO-рішення нижче фіксує його історію; обкладинки тепер редагуються окремо через призначення фото в адмінці, а портфоліо збережено.

## Рішення та причина

| Рішення | Проблема → користь → перевірка |
|---|---|
| Головна для манікюру | Загальний слоган/mood-photo відсували вибір → H1, адреса, перші дві названі процедури/ціни, справжня робота, Direct/телефон; манікюрний прайс відкритий → desktop/mobile + no-JS |
| Дві окремі послуги | Один title/H1 і змішаний прайс давали другорядним запитам довгий шлях → власні прайс, пояснення, фото, canonical і запис → HTTP/SSR/hydration на кожному URL |
| Зберегти стек | Початковий SSR уже працював → розширено спільний renderer, без нових runtime/dependency/інфраструктурних витрат → обидва runtime suites + dry-run |
| Редаговані послуги | Редактор змінював лише суми, а пояснення були сталими → назви/деталі/позиції/overview/booking/note публікуються однією ревізією → authenticated publication test + незалежна UI-публікація |
| Спільні факти | Графік, поверх і відео були константами → optional керовані поля контактів, introduction; схема використовує ті самі значення → тест очищення годин прибирає openingHours |
| Історія D1 | UPDATE втрачав попередній документ → additive history table + triggers; старі JSON не переписуються → snapshot/history/conflict tests |
| Шлях запису | Нові URL випадали з root-only аналітики → той самий allowlist подій на трьох сторінках, один beacon, без PII → trusted clicks у локальному Worker |

## Дані та публікація

Поточні production prices/contacts/gallery залишаються джерелом істини. Seed-файли не переносяться поверх D1. Нові optional поля сумісні зі старими JSON; початкові пояснення застосовуються під час читання. Якщо назви/склад послуг змінено, а власного пояснення ще немає, опис формується з актуальних позицій замість старої заяви про склад процедур. Задане власником пояснення зберігається й редагується разом із прайсом.

Legacy `summary` збережено у JSON для сумісності й rollback, але прибрано з публічної подачі та редактора: воно не є надійним мінімумом усіх позицій (наприклад, ремонт нігтя дешевший за манікюр). Показуються **назва + власна ціна конкретної процедури**, а не ручна «ціна від».

Можна додавати/прибирати позиції всередині шести фактичних категорій (1–30). Видалення набуває чинності після збереження; старі Node ревізії зберігаються. D1 history потрібно ввімкнути за checklist **до поновлення редагувань власником**. Нових категорій чи вигаданих послуг автоматично не додається. Галерея зберігає порядок і фото; optional категорія керує вибором першого фото й добіркою послуги, старі записи читаються за підписом.

Порожні години не дають `openingHoursSpecification`; довільний графік показується як текст і не вгадується у schema. Точний щоденний інтервал розмічається лише у підтримуваному форматі. Зміна адреси в редакторі очищає старий поверх/відео для перевірки власником; відома Maps-точка вже має перевірку відповідності початковій адресі.

Telegram story URL збережений у даних, але контактна кнопка отримує профіль того самого username. Direct і телефон редагуються як раніше. Кнопки означають звернення, а не підтверджений запис.

## URL

| Вхід | Результат |
|---|---|
| `/` | 200, локальний манікюр, self-canonical |
| `/pedicure` | 200, педикюр, self-canonical |
| `/laminuvannia-vii` | 200, ламінування вій, self-canonical |
| `/index.html` | 301 → `/` |
| `/pedicure/`, `/pedicure/index.html` | 301 → `/pedicure` |
| `/laminuvannia-vii/`, `/laminuvannia-vii/index.html` | 301 → `/laminuvannia-vii` |
| `/manicure` і slash/index.html варіанти | 301 → `/` — сумісний alias того самого наміру |
| `/lashes` і slash/index.html варіанти | 301 → `/laminuvannia-vii` — сумісний alias |
| `/brows`, випадкові та невідомі вкладені URL | 404, без перенаправлення на нерелевантну головну |

Query-параметри зберігаються в redirects, canonical їх не містить. Історична документація каже, що старі service routes не були опубліковані: aliases не подаються як відновлення доведеного старого трафіку. Для існуючої головної URL не змінюється. HTTP/www normalization зберігається в production Worker/Cloudflare; для альтернативного Node deployment HTTPS/host-normalization виконує налаштований reverse proxy, а path-normalization — Express.

Sitemap містить рівно три canonical URL. `lastmod` пропущено, бо немає одного правдивого timestamp для всіх code/content змін. Розмітка: справжній BeautySalon, WebSite, окрема WebPage/Service, відповідний видимий каталог і breadcrumbs. Без aggregateRating/Review, вигаданих координат чи FAQ rich-result обіцянок. Slash-ціни не перетворюються на довільну числову ціну.
