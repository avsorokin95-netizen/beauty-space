# Перевірка SEO-ефекту

**D = фактична дата релізу**, яка ще не настала в межах цього завдання. 2026-10-01 — дата підготовки. Після deployment зафіксувати D, Git SHA, Cloudflare version ID, час міграції, склад релізу та baseline. Наведені нижче перевірки не заплановані як фонові автоматизації.

## Що порівнювати

| Кластер небрендових запитів | Ціль | Головні метрики |
|---|---|---|
| манікюр Софіївська Борщагівка; манікюр ЖК Софія; манікюр Боголюбова; манікюр зі зміцненням/покриттям + локація | `/` | GSC покази, кліки, CTR, позиції саме цього кластера; релевантні звернення |
| педикюр Софіївська Борщагівка; педикюр ЖК Софія; педикюр ціни + місцевість; варіант «педікюр» лише для аналізу | `/pedicure` | Ті самі метрики окремо від манікюру |
| ламінування вій Софіївська Борщагівка; ламінування вій ЖК Софія; фарбування вій + місцевість | `/laminuvannia-vii` | Ті самі метрики, без націлення на непідтверджене нарощування |
| манікюр/педикюр/вії Вишневе | Відповідна сторінка тільки якщо Google дає релевантні покази | Другорядний зріз сусідньої аудиторії; бізнес не розташований у Вишневому |

Окремо згрупувати бренд: Beauty Space Victoriya, beauty.space.victoriya, Вікторія + назва/адреса та реальні варіанти з GSC. Не домішувати брендові кліки до оцінки нової локальної видимості.

GSC baseline: останні повні 28 днів до D + попередні 28 днів; за наявності — довший сезонний контекст. Тип пошуку Web, окремо Україна/інші країни, mobile/desktop, запит×сторінка. Зберегти exports приватно. Перевірити Indexing, sitemap, URL Inspection трьох URL, Google-selected canonical, Manual Actions, Security Issues. Зараз ці дані не отримані, тож не заявляється ні падіння, ні санкції, ні їх відсутність.

Cloudflare: account/site/token та історичні події збережені. З D події охоплюють три сторінки замість однієї; загальні counts можуть зрости через покриття й більше місць для натискання. У D1 event counters немає acquisition source, landing page, visitor ID або підтвердження завершеного запису. Тому їх **не можна назвати органічними лідами** або унікальними клієнтами. Власник може приватно вести щотижневу кількість нових звернень/підтверджених записів за послугами та відповідями на нейтральне «Як ви нас знайшли?»; у вебподії персональні дані не передаються.

GBP Performance рахувати окремо: доступні пошукові терміни, переходи на сайт, натискання телефону, запити маршруту. За підтримки поточного звіту використовувати UTM-посилання сайту `?utm_source=google&utm_medium=organic&utm_campaign=gbp`, але не обіцяти атрибуцію, якої немає в аналітиці. Не складати GSC, GBP і D1 counters як унікальних людей.

## Контрольні точки

| Коли | Перевірка | Рішення |
|---|---|---|
| D+14 | Статуси, sitemap, індексація, chosen canonical, оновлений контент Google, перші релевантні покази; перевірка запису | Усунути технічні помилки. Відсутність росту за два тижні не є доказом провалу |
| D+28 | Зіставити повні рівні періоди за кластером/сторінкою/пристроєм/країною; CTR оцінювати разом із позиціями й складом запитів; кількість справжніх звернень | Якщо покази релевантні, а кліків мало — перевірити snippet/пропозицію. Якщо кліки є, а звернень мало — дослідити шлях запису та фактичну конкурентність |
| D+56 | Тенденція за кількома тижнями, розподіл манікюр/педикюр/вії, GBP окремо, нові запити й можливе дублювання намірів | Продовжувати корисні зміни за даними; не множити сторінки автоматично. За малої вибірки прямо вказати невизначеність |

Якби D був 2026-10-01: 2026-10-15, 2026-10-29, 2026-11-26. При іншому deployment дати зміщуються. Це строки спостережень, не гарантії топу або приросту.

Очікувана користь — краща відповідність локальному комерційному наміру та коротший шлях до усвідомленого звернення. Фактичний SEO-ефект потрібно підтвердити Google-даними й реальними зверненнями, а не кількістю змінених файлів, локальним build або одним ручним пошуком.
